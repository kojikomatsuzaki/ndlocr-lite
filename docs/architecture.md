# 構成と設計理由

## 責務

| 部分 | 責務 |
| --- | --- |
| `ocr.yml` | 手動起動、実行環境、工程の可視化、Artifactsへの受け渡し |
| `default.yaml` | エンジン・モデルの固定値、画像制限、実行時間の正本 |
| `prepare_input.py` | パス・形式・画像内容・ZIPを検査し、原画像と同じバイト列を準備 |
| `run_ocr.py` | 公式CLIの呼び出し、成功判定、画像単位の記録 |
| `generate_metadata.py` | 書誌情報と技術情報の分離、YAML正本からJSON生成 |
| `create_sample.py` | 著作物を持ち込まない接続試験用画像の生成 |

## データの流れ

入力画像またはZIP → バイト列を変えない作業用コピー → 固定した公式CLI → 生TXT/JSON/XMLと処理記録 → Artifacts。
原資料や画像は本基盤の正本ではありません。元の資料管理環境で保管してください。
校正済みの翻刻は別工程とし、対応する入力画像SHA-256と生OCRの実行IDを引き継ぎます。

## 公式ソフトウェアとの境界

公式READMEの`python ocr.py --sourceimg ... --output ...`を`src/`で実行します。
CPUと4モデルのパス、2つの文字・レイアウト設定を明示し、その他は固定コミットの既定値に従います。
公式OCR内部で行われる画像のRGB変換、縮尺変更、読み順整序などはエンジンの処理です。
それに加えて原画像の補正やテキストの推測修正を行う処理はありません。

同じ名前の異なる拡張子でも出力が衝突しないよう、画像ごとに別の出力ディレクトリを用意します。
プロセスの終了コードに加え、TXT・JSON・XMLの存在とUTF-8、JSON/XMLの構文を検証します。
これは空出力の誤認や出力先の誤りを検出するためであり、文字の正誤を判定するものではありません。

## 再現性と限界

- 公式ソースは完全なコミットSHAで固定し、実行前にHEADと追跡ファイルの未変更を確認します。
- ONNXは公式Git blob IDと照合し、SHA-256も採録します。Git LFSポインター等に置き換わっていれば不一致で停止します。
- 入力画像、各生出力、設定ファイル、文字・レイアウト設定をSHA-256で記録します。
- インストール済みパッケージの名前と版、Python、OS、runnerイメージ情報、ワークフローSHAを保存します。
- YAMLメタデータが正本、メタデータJSONはその派生です。OCRの生TXT/JSON/XMLは公式の並列出力としてすべて保持します。
- OSイメージと間接依存の完全固定、コンテナイメージ保存は未実装です。必要になれば追加します。

## 安全な失敗と保守

利用者入力はシェルのソースへ埋め込まず、環境変数から引用して渡します。
GITHUB_TOKENの権限は`contents: read`のみ、checkout後に認証情報を残しません。
原資料ファイル名はログ画面へ直接展開せず、公式CLIのログはファイルに保存します。
メタデータへ環境変数や認証情報を一括保存しません。

ZIPの絶対パス、親ディレクトリ参照、バックスラッシュ、ドライブ記法、制御文字、特殊ファイル、暗号化、重複パスを拒否します。
サイズ・項目数・圧縮比を検査し、展開時にも読み出し量を制限します。
不明な拡張子は黙って無視せず失敗にします。名前・内容の一部を勝手に採用しないためです。

画像ごとのエラーを採録して残りを続行し、一件でも失敗すればジョブを失敗にします。
出力先が非空なら起動を拒否し、過去の成果物を上書きしません。
依存導入・入力パス解決などメタデータ作成前の失敗は、Actionsの工程ログと`workflow-status.json`を参照してください。
